# Inspekta code review method

Read-only. Cite `file:line` for every finding. Prefer fewer, high-value findings over a
long list of nits — group repeated issues ("same pattern in 9 handlers, e.g. …").

## 0. Orientation
- Architecture: Grit **single** (SPA embedded via `go:embed`), **double**, or **triple**
  (`apps/api`, `apps/web`, `apps/admin`, `packages/*`). Read `.grit/project-profile.md`.
- Grit convention: **handler → service → model**. Handlers parse the request, call *one*
  service method, write the response. Business logic in handlers is a finding.
- Generated vs hand-written code: don't nitpick generated files unless they were edited badly;
  admin resources live in `apps/admin/resources/`.
- Use `grit` CLI docs / `grit-with-docs` skill when unsure of a convention.

## 1. Go API (Gin)
- Errors: wrapped with context (`fmt.Errorf("…: %w", err)`), never swallowed, no `panic` in request path
- Consistent JSON error shape and HTTP status codes; no leaking internal errors to clients
- Input binding + validation (`binding:"required"` / validator) on every write endpoint
- `context.Context` passed through to DB calls; timeouts on outbound HTTP
- No global mutable state; goroutines have lifecycle/cancellation; no leaked tickers
- Config from env, not hard-coded; secrets not committed (`.env` in git, keys in code)

## 2. Data layer (GORM / Postgres)
- **N+1 queries** (loops calling DB; missing `Preload`/joins)
- Unbounded `Find(&all)` on list endpoints — pagination + max page size
- Missing indexes on FK / filter / sort columns; missing unique constraints backing business rules
- Transactions around multi-step writes; `Save` overwriting zero values unintentionally
- Raw SQL with string concatenation → injection; `Where("name = " + x)`
- Soft-delete consistency; migrations reversible and not edited after release
- `SELECT *` on wide tables where a few columns are needed

## 3. Security
- **AuthZ on every route**, not just authN — can user A read/edit user B's record (IDOR)?
- Role checks server-side, not only hidden buttons in the UI
- Password hashing (bcrypt/argon2), JWT expiry/refresh, token storage (httpOnly cookies vs localStorage)
- CORS not `*` with credentials; CSRF where cookies are used; rate limiting on auth endpoints
- File uploads: type/size limits, private buckets, signed URLs (S3/R2/MinIO)
- Sensitive data in logs; verbose errors in production; debug routes left on
- Dependency risk: very old versions of key libs

## 4. Background jobs (Redis / asynq)
- Idempotent handlers, retries with backoff, dead-letter handling, no huge payloads in tasks

## 5. Frontend (Next.js / React / TS / Tailwind / shadcn)
- `any` and `@ts-ignore` usage; types generated by Grit actually used
- Data fetching via the generated hooks / React Query; no fetch-in-useEffect duplicates;
  sensible `staleTime`; cache invalidation after mutations
- Loading/empty/error handling present in components (ties to QA states)
- Re-render hotspots: inline objects/functions in large lists, missing keys, context overuse
- Bundle: heavy libs imported whole, no dynamic import for heavy pages, unoptimised images
  (`next/image`), client components where server components would do
- Forms: schema validation (zod) shared with API types; disabled submit while pending
- Accessibility in code: buttons vs divs with onClick, missing labels/alt, focus management in modals
- Hard-coded colours instead of Tailwind/shadcn tokens (breaks dark mode)

## 6. Maintainability
- Files > ~400 lines or functions > ~60 lines doing many things; duplicated logic
- Dead code, commented-out blocks, TODOs older than the feature
- Naming clarity, package boundaries, circular deps between packages

## 7. Tests & tooling
- Tests exist for services and critical handlers; table-driven Go tests; any e2e?
- CI runs lint, vet, typecheck, tests; formatting enforced
- Docker/compose sane; health checks; production build settings

## Finding format (code-review.md)
~~~~
### CR-04 · High · Client create endpoint is not idempotent and has no unique constraint
**Where:** apps/api/internal/handlers/client.go:42, internal/models/client.go:12
**Problem:** … **Impact:** duplicate records (seen live as QA-F03).
**Fix:**
```go
// add unique index
Email string `gorm:"uniqueIndex;not null"`
```
~~~~

Score with the **Code rubric** in `inspekta-report`.
